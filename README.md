# الموقع العقاري العربي — ملفات التطبيق الكاملة

## أين index.html؟

هذا تطبيق **Next.js App Router + React + TypeScript + PostgreSQL/Drizzle**، وليس موقع HTML ثابتًا. لا يتطلب `index.html` أو `indx.html` في جذر المشروع. الصفحة الرئيسية في `src/app/(site)/page.tsx`، والتخطيط الأساسي في `src/app/layout.tsx`. Next.js يولّد HTML ويقدمه من الخادم عند التشغيل.

فتح ملفات TSX أو HTML بالنقر المزدوج، أو رفع المشروع إلى استضافة ملفات ثابتة فقط، لن يشغّل المصادقة وقاعدة البيانات ورفع الصور. لا تحوّل المشروع إلى `output: "export"` لأن وظائفه تحتاج خادمًا.

يمكنك فتح `START-HERE.html` محليًا لقراءة تعليمات عربية مختصرة؛ هذا **دليل فقط** وليس الموقع.

## أفضل طريقة لتنزيل المصدر كاملًا

في لوحة **المالك** افتح **النشر والروابط → تحميل المشروع كاملًا ZIP**. الحزمة تتضمن كل ملفات `src/` و`public/` و`scripts/` وملفات الإعداد و`package-lock.json` والقوالب المخفية الآمنة، وتضيف `PROJECT-MANIFEST.json` بأسماء الملفات وأحجامها وبصمة SHA-256 لكل ملف.

بعد فك الضغط ستجد مجلد `arabic-real-estate`. افتح الطرفية داخله (حيث `package.json`) ثم افحص النسخة قبل تثبيت الحزم:

```bash
node scripts/verify-download.mjs
node scripts/check-deployment.mjs --files-only
```

ملف `PROJECT-FILES.json` هو قائمة تسليم مستقلة تشمل جميع ملفات المصدر المطلوبة، والصفحات ومسارات API وطرق HTTP. لذلك لا يكفي نجاح البناء إن اختفت صفحة لا يستوردها ملف آخر. مُصدّر ZIP يرفض إنشاء الحزمة إذا غاب أي ملف مسجّل، وفحص التنزيل يقارن قائمتي التسليم والبصمات.

الأمر الأول يتحقق من **كل ملف** مسجل في الحزمة، ويكشف النقص أو تلف المحتوى. إذا عدّلت الملفات بنفسك لاحقًا ستختلف البصمات طبيعيًا؛ اجعل هذا الفحص أول خطوة بعد التنزيل. فحص البصمات يكشف اختلاف الملفات، لكنه ليس توقيعًا يثبت هوية ناشر الكود.

إذا نزلت المشروع من زر المنصة العادي، قد لا تجد `PROJECT-MANIFEST.json` لأنه يُنشأ داخل حزمة ZIP الخاصة بنا. افحص على الأقل `--files-only`، أو استخدم تنزيل المالك الكامل بدلًا منه.

## ما لا يُضمّن عمدًا

- `.env` وملفات الأسرار ومفاتيح الحسابات: غير مرفقة لحماية المالك. استخدم `.env.example` الفارغ.
- `node_modules/`: تتولد عند `npm ci`، وليست ملفات ناقصة.
- `.next/`: يتولد عند البناء، ولا يُرفق ناتج بناء قديم.
- `uploads/` والصور المرفوعة وسجلات PostgreSQL: **الحزمة ليست نسخة احتياطية لبيانات العملاء أو قاعدة البيانات**. نقل المحتوى يحتاج تصدير قاعدة البيانات والصور بصورة مستقلة وآمنة.
- ملفات Git والجلسات والسجلات المحلية.

## التشغيل على جهازك

1. ثبّت Node.js 22 LTS وnpm، وجهّز PostgreSQL.
2. فك الضغط، ثم افتح الطرفية في المجلد الذي يحتوي على `package.json`.
3. افحص النسخة، ثم ثبّت الحزم بالإصدارات المقفلة:

```bash
npm ci --include=dev
```

بعد تثبيت الحزم، افحص الاستيرادات وكل المسارات المطلوبة:

```bash
node scripts/check-source.mjs
```

هذا فحص قراءة فقط: يكشف الملفات المحلية المستوردة وغير الموجودة، وأي حزمة مستخدمة غير معلنة، وطرق HTTP الناقصة في المسارات. يعتمد على TypeScript المثبّت مع devDependencies، ولا يتصل بقاعدة البيانات أو يغيّر المحتوى. ملف `.nvmrc` يحدد Node.js 22؛ استخدمه إن كان جهازك يدعم nvm.

4. انسخ `.env.example` إلى ملف `.env` داخل المشروع، ثم أدخل القيم الفعلية خصوصًا `DATABASE_URL` و`AUTH_SECRET` وبيانات تهيئة المالك لأول مرة. اختر سرًا عشوائيًا وكلمة مرور خاصة قوية؛ لا توجد أسرار جاهزة في الحزمة. اترك `UPLOAD_DIR` فارغًا على جهازك ليستخدم `./uploads`، واضبطه إلى مسار مطلق على Volume دائم عند النشر.
5. أنشئ الجداول، ثم هيّئ المالك:

```bash
npx drizzle-kit push --config=drizzle.config.ts
npx tsx scripts/seed.ts
```

`seed.ts` لا ينشئ الجداول. يهيّئ المالك وأنواع العقارات بعد وجودها، ويحافظ على المالك الموجود ما لم تطلب صراحة إعادة تعيين كلمة المرور. لا يستخدم بريدًا أو كلمة مرور افتراضية.

6. للتطوير المحلي:

```bash
npm run dev
```

افتح `http://localhost:3000` بعد بدء الخادم. رابط الإدارة هو `/admin` على نفس العنوان.

7. للنشر الفعلي: نفّذ `npm run build` ثم `npm run start` على استضافة Node.js، مع PostgreSQL إنتاج وتخزين صور دائم، وفق `DEPLOYMENT-AR.md`.

لا تشغّل خادم التطوير كإنتاج، ولا ترفع `.env` إلى Git. يجب أن يكون `UPLOAD_DIR` مسارًا مطلقًا تدعمه مساحة تخزين دائمة في الاستضافة.

## إعادة تصدير الحزمة من ملفاتك

بعد تثبيت الحزم، تستطيع بناء ZIP جديد محليًا:

```bash
npx tsx scripts/export-project.ts
```

سيُحفظ في `exports/arabic-real-estate-source.zip`. هذا المجلد غير عام وغير مرفوع إلى Git. لا تضع حزمة الكود في `public/` أو تشاركها مع أشخاص غير مخولين.

## المراجعة والاختبارات

اقرأ `AUDIT-REPORT-AR.md` للفروق بين المعاينة وإعدادات الإنتاج، والأخطاء التي اختُبرت والنقاط التي لم تُفعّل. صفحة `/admin/diagnostics` تُظهر الحالة الحالية للمالك. النسخة ليست موصولة بـSupabase Auth/Storage/RLS، والاستعادة بالبريد غير مفعّلة؛ لا تعتبرهما موجودتين بمجرد نجاح البناء.

اختبارات `scripts/audit-core.ts` و`scripts/audit-browser.mjs` تُشغّل فقط على بيئة اختبار. اضبط متغيرات `AUDIT_BASE_URL` و`AUDIT_ADMIN_EMAIL` و`AUDIT_ADMIN_PASSWORD` سرًا، ثم فعّل `AUDIT_ALLOW_MUTATIONS=yes`. السكربتات تنشئ سجلات مؤقتة وتحاول حذفها بالمعرف الفردي؛ لا تُشغّلها على إنتاج حي دون موافقة ونسخة احتياطية. اختبار المتصفح يحتاج Chromium من Playwright ومتطلباته في بيئة الاختبار.

## فحوص البناء

```bash
npx next typegen
npm exec tsc -- --noEmit --pretty false
npm run build
```

راجع `DEPLOYMENT-AR.md` للنشر بدون شراء دومين خاص أو لربط دومينك. وجود الملفات ونجاح البناء لا يصدران رابط إنتاج ولا يثبتان فهرسة Google.
